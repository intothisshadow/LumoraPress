# Downloads

A dedicated admin screen to manage downloadable files and links — the kind of "download manager" plugin classic WordPress sites commonly used, rebuilt for Lumora Press's own content model.

## What this plugin does

- **Downloads → All Downloads**: a real list table — ID, Title, Category, Shortcode, Type, Status, and Date columns (the Shortcode column shows the `[lumora_downloads download_id="…"]` that displays that one download, ready to copy into a post; a trashed download or one with nothing to serve shows a dash) — with a category filter, sortable columns, Live/"No file attached"/Trash status tabs (the middle one lists only downloads with nothing to serve, so incomplete entries are easy to find), bulk actions, and pagination, the same conventions the Posts/Pages list screens use.
- **Downloads → Add New**: add a new download — a title, description, and category, plus either an uploaded file or an external URL. The Description field uses the same shared WYSIWYG/Markdown/HTML editor Posts and Pages use, with the same format-switching UI. A category can also be created inline from the same screen. The same screen doubles as the editor for an existing download, where a download shows a preview image — an image thumbnail, or a file-type badge for non-image files — visible immediately after a successful upload on Add too.
- **Downloads → Import from GitHub**: add a download from a public GitHub repository in a few clicks. Save your GitHub username once and pick a repository from a list, or paste the address of any public repository. A preview shows what will be imported before anything is saved: the title (from the README's first heading; a heading that is really a file name such as `FocusWriter-Theme_FAN_XenaWarriorPrincess_SunlightonSteel` is turned into `FocusWriter Theme - Xena Warrior Princess: Sunlight on Steel`, and you can correct it in the preview), the README as the description (editable, and shown as Markdown), and the screenshots found in the repository's `screenshots` folder, each with a checkbox. The import creates a Media folder named after the repository, copies the ticked screenshots into it, shows them in a Screenshots section after the description, uses the first one as the download's thumbnail, and links the download to GitHub's zip of the repository's default branch, so nothing is stored on your server and the link always serves the latest code. Progress is shown without leaving the page, and an import that fails part way removes what it had copied.
- **Update from GitHub**: a download made this way has an "Update from GitHub" button on its edit screen. Click it, then "Check for changes", to see only what is different on GitHub (a changed README, new, changed, or removed screenshots, a renamed default branch), each with a checkbox. A description or title you have edited by hand since the import is left unticked so an update never overwrites it by accident, and a screenshot removed on GitHub is kept here unless you tick it. Nothing updates on its own; GitHub is contacted only when you click.
- **Link to GitHub**: a download that wasn't imported from GitHub (one you added by hand) can be linked to its repository afterwards, from a "Link to GitHub" panel on its edit screen, so it gains the Update from GitHub button too. Linking changes nothing on the download: its title, description, link, and files stay exactly as they are. Screenshots already in the download's Media folder are matched to the repository's files by their content, so nothing is downloaded twice, and a check screen shows the matches before you confirm. After linking, the update screen offers the README with its box unticked whenever your own description differs, and offers any screenshots the download doesn't have yet.
- **Downloads → Categories**: categories can have a parent, and the list shows each sub-category indented under its parent. A category whose parent is in the Trash still appears, at the top level, so nothing disappears from the list. The Trash view stays a plain list.
- **Downloads → Shortcodes**: reference docs for `[lumora_downloads]` and `[lumora_recent_downloads]`, with real examples built from the site's own categories.
- **Trash**: moving a download to Trash hides it from the public `[lumora_downloads]` output and the admin list's default view, but leaves its underlying file/redirect untouched — restore it from the Trash tab, or permanently delete it from there once you're sure. Permanently deleting a download removes its underlying file or redirect too, unless a duplicate of it still exists (see Duplicate, below) — nothing orphaned is left behind once nothing references it.
- **Duplicate**: clones a download's title/description/category as a new entry, sharing the original's underlying file/redirect rather than copying it.
- `[lumora_recent_downloads]` lists every live download newest first, a page at a time (`per_page="10"`, 1–100; add `category="…"` or `category_id="…"` to limit it to one category, and `show_size="1"` for file sizes). Page links appear below the list when there is more than one page, using a `downloads_page` address parameter so they never clash with a post list's own paging.
- `[lumora_downloads category="Folder Name"]` (or `category_id="13"`, which wins if both are given) shows a category's downloads anywhere in post/page content — a title, a link, an optional file size (`show_size="1"`) and description. Trashed downloads never appear here. Add `per_page="10"` (1–100) to split a long category into pages, with page links below the list using the same `downloads_page` address parameter as `[lumora_recent_downloads]`.

## Notes

- In every public download list, each download starts with a bold "Download:" before its link. A theme can restyle it with the `.lp-downloads-list__label` class.

- The GitHub import only reads public information. It sends GitHub the repository's name (or your GitHub username, to list your repositories) and your server's address, nothing else, and only while you are using the import or update screens. GitHub allows a limited number of such requests an hour for anonymous visitors; if you reach that, the screen says when it resets. Private repositories are not supported.
- A README's simple HTML (centered headers, badges, line breaks) is converted to Markdown when imported, because descriptions written in Markdown don't display raw HTML. Complicated layouts such as tables built from HTML may need a tidy-up in the description afterwards.
- Themes style the Screenshots section of an imported description as small tiles side by side. A custom theme that doesn't can copy the `#screenshots + p a > img` rule inside `.lp-downloads-list__description` from Lumora Classic's stylesheet.

- A file-type download reuses the existing Media library, and a URL-type download reuses the existing Redirects system (so it keeps real hit-counting) — Downloads is a thin, unified admin layer over both, not a separate storage mechanism.
- If the WordPress Importer plugin is also active, a download added here automatically appears in that plugin's own imported-download shortcode output too, filed by the same category.
